# AGENTS.md — coding

Public Go SDK for embedding the coding agent (Pi `packages/coding-agent` core): Session, Model Runtime, tools, compaction, resources, settings, auth. Package doc: `doc.go`.

## Layout
- Root package: `create_agent_session.go`, `session*.go`, `compaction*.go`, `auth_storage.go`, resource discovery.
- `cli/` — CLI entry (`cli.Main`), print/JSON/RPC modes, subcommands, help text (`help_upstream.txt` regenerated by `make help-text`).
- `extension/` — extension API and host (own AGENTS.md).
- `piglet/`, `pigletbuild/` — Piglet schema, CLI, build. Schema `piglet/piglet.schema.json` is generated (`make piglet-strip-ids`).
- `packagecontent/`, `extensionset/`, `source/`, `mcpext/`, `piglogin/`, `rpcclient/`, `secretresolver/`, `hookconfig/`.
- Interactive app lives in `internal/codingagent/`, not here.
- Upstream: `.upstream/current/packages/coding-agent/src/core/agent-session.ts`, `model-runtime.ts`.

## Contract
- One Session owns one Model Runtime. TUI, print, JSON and RPC use that runtime.
- Session replacement cancels and drains prior work.
- Persistence, paging, compaction and reconciliation preserve order and identity.
- Agent `Send`/`Continue` only from `session*.go`.

## Failure modes
| Failure | Detection | Required result |
|---|---|---|
| A mode uses a different model path | one request in every mode | same request, events, result |
| Session replacement leaks prior work | replace an active Session | prior runtime cancelled and drained |
| Paging loses or duplicates an append | append during page transfer | each entry once, in order |
| Resume scans/copies full history on input | editor and command paths on a large Session | bounded work |
| Compaction races queued input | queue input during compaction | documented queue ordering |
| Poisoned history breaks a later turn | aborted, errored, empty, orphaned entries | recover or fail at the owning boundary |
| Shutdown leaves work or files open | cancel during provider, tool, extension activity | owned work drained, resources closed |

## Evidence
- State-transition and ordering cases first. Isolated tests for parsers, paging, reconciliation; complete mode paths for runtime ownership, replacement, compaction, resume.
- Ordinary and large Sessions; record latency, allocations, memory, file reads, goroutines, cancellation.

## Cross-updates
- CLI flag or setting change → `make generate` (help, schemas, docs mirrors); user docs in `docs/site/docs/` and `internal/pigdocs/content/`.
